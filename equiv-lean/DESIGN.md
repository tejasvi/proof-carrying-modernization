# equiv-lean: design and bridge contract

equiv-lean proves behavioural equivalence `∀ x, f_target x ≈ f_source x` between programs
produced by five Lean encodings, without changing any of them:

| encoding | front end | meaning of a function | pinned copy |
|---|---|---|---|
| cirlean (C/C++) | cir2lean | `CIR.evalCall ctx sym args m : CIR.Res (Exit × Mem)` (`ok`/`ub`/`div`, `partial_fixpoint`) | `../equivlean_work/vendor/cirlean-88e6008` @88e6008 |
| coblean (COBOL) | cobol_program loader | `Cobol.Program.run P env fuel st : Signal × State` (fuel) | `../equivlean_work/vendor/coblean-20261024T1149Z` (snapshot 20261024T1149Z) |
| JimpleLean (Java) | Soot + jimple_import | `Jimple.MExec P m args σ o` (big-step relation, partial correctness) | `../equivlean_work/vendor/JimpleLean-20261024T1029Z` (snapshot 20261024T1029Z) |
| StrictTS (TypeScript) | ts2lean (strictts/frontend) | `StrictTS.callFun I P f vs : JS TT (Val TT ret)`, `JS.exec m w : Option (Except Exc α × World TT)` | `../equivlean_work/vendor/strictts-a15926a` @a15926a |
| Aeneas (Rust) | Charon + Aeneas | `f x : Aeneas.Std.Result α` (`ok`/`fail e`/`div`, ITree-based) | `../equivlean_work/dl/aeneas` @fdebf20 (`backends/lean`) |

All five are Lean v4.35.0; Aeneas brings Mathlib v4.35.0. They import together in one file
without name clashes (checked 2026-10-23).

## Core (EquivLean/Core, core Lean only)

* `Behaves C O` (`Core/Behaves.lean`): outcome semantics of a *closed* computation `c : C`:
  `Runs c o` (can finish with observable outcome `o`) and `Safe c` (cannot go wrong).
  `wp c Q := Safe c ∧ ∀ o, Runs c o → Q o`. Classes `Behaves.Total` (safe ⇒ terminates) and
  `Behaves.Det`. Instances for `Id`, `Except`, `Option` (and through `.run`, for `StateT`,
  `ExceptT` stacks).
* `Sim R t s := Safe s → Safe t ∧ ∀ ot, Runs t ot → ∃ os, Runs s os ∧ R ot os`
  (`Core/Sim.lean`); `Equiv R t s` both ways; `FSim`/`FEquiv`/`EquivOn` for functions.
  Key lemmas: `sim_iff_wp` (tactic form: source in a hypothesis `wp s P`, target in the goal
  `wp t (fun ot => ∃ os, P os ∧ R ot os)`), `Sim.wp_cut` (THE product-program step),
  `Sim.trans`, `Sim.of_seq`, `sim_iff_of_runs`, `EquivOn.changed_subset`.
* `Simulates T S` typeclass (`t ⊑ s`), default instance from `Behaves` + `Corr OT OS`;
  `Equivalent` (`t ≈ s`). `Corr A B` is the representation-refinement class.
* `LoopShape L iter cls` (`Core/Loop.lean`): a loop = one iteration `iter s` whose outcome is
  classified by `cls : OD → O ⊕ σ` (`.inl o` leave with loop outcome `o`, `.inr s'` next
  iteration). `LoopShape.Terminates`: a safe loop iterates finitely often (Acc).
  Rules: `wp_loop` (one-sided), `sim_loop` (lockstep + variant), `sim_loop_of_terminates`
  (lockstep, coupling invariant only), `wp_loop_rel` (hypothesis form for tactics),
  `sim_loop_stutter` (scheduler: both/left/right).

## Bridge contract (one directory per encoding, `EquivLean/Bridge/<E>/`)

1. `Behaves.lean`: `Behaves` instance(s) for the encoding's closed computations, with the
   choice of `Safe`/`Runs` documented (what is an observable outcome, what is unsafe);
   `Total`/`Det` instances where true; `@[simp]` lemmas turning `wp` into the encoding's
   native judgement (and through bind/ite/match).
2. `Loops.lean`: `LoopShape` for every loop construct of the encoding, and
   `LoopShape.Terminates` (fixpoint induction with `Lean.Order.admissible_flatOrder` /
   `admissible_pi_apply`, or fuel).
3. `Obs.lean`: observation relations for "same observable behaviour" (e.g. caller-visible
   memory modulo fresh allocation) and the encoding-level `EquivOn` statement.
4. `Corr.lean`: `Corr` instances and refinement lemmas from the encoding's values to the
   shared mathematical models in `EquivLean/Repr` (Int/BitVec fixed width, Decimal, List,
   finite maps, records).
5. `Tactic.lean`: an `equiv_<e>` tactic (start, symbolic execution of both sides with the
   encoding's own simp sets/executor, lockstep loops via `wp_loop_rel`, leaves via
   `simp`/`omega`/`bv_decide`/`grind`).
6. Demos under `EquivLean/Demo/` on REAL front-end output (old and new versions generated by
   the actual translator), each theorem with only the standard axioms (plus `bv_decide`'s
   native-code axiom where used; say so).

## Conventions

* Never edit the pinned copies or the sibling repositories (`~/cirlean`, `~/coblean`,
  `~/jimplelean_work`, `~/strictts`). Generated Lean from a front end goes under
  `EquivLean/Demo/Gen/<E>/`, sources under `examples/<E>/`.
* Single-file checks: `scripts/lean1.sh F.lean` (no Lake lock, 1 thread, nice 10, 64 GiB cap);
  `scripts/lean1.sh -o F.lean` also writes F's olean so other files can import it.
  `lake build` only by the integrator.
* Scratch: `../equivlean_work/scratch/<agent>/`. Never `/tmp` or `/dev/shm`.
* Core changes (EquivLean/Core/*) go through the integrator (main session).

## Tactics (generic layer, `EquivLean/Tactic`)

| tactic | does |
|---|---|
| `equiv_split` | unfold `Equiv`/`FSim`/`FEquiv`/`EquivOn`/`⊑`/`≈` to `Sim` goals |
| `equiv_intro P hs` | `Sim R t s` ⟶ `hs : wp s P ⊢ wp t (fun ot => ∃ os, P os ∧ R ot os)` |
| `equiv_exec [lemmas]` | symbolic execution of both sides (bridges extend it) |
| `equiv_cases` | split every `if`/`match` in the goal and the hypotheses (aligned path pairs) |
| `equiv_prune` | close a pair of contradictory paths (`contradiction`, `omega`, `simp_all`, `grind`) |
| `equiv_leaf`, `equiv_close` | pick the source outcome from the hypothesis; `rfl`/`simp`/`omega`/`decide`/`bv_decide`/`grind` |
| `equiv_body [defs]` | one lockstep iteration (or two straight-line programs) end to end |
| `equiv_loop I (with R)? using h₁, h₂, ht` | lockstep loops with explicit shape lemmas |
| `equiv_loop_auto I (with R)?` | lockstep loops of any two registered encodings (`Bridge/Registry.lean`) |
| `equiv_loop_same` | `equiv_loop_auto` with the coupling "equal loop states" (refactors that keep the state) |
| `equiv_loop_async I V sched (with R)?` | asynchronous pairing (unrolled/split/peeled loops): `sched` picks both/left/right per product state |
| `equiv_call` | use an `@[equiv_spec]` relational specification at a pair of calls |

Bridge tactics: `equiv_cir` (generated couplings with `Bridge/Cir/AutoCouple`, pointer arguments
bounded to the caller's blocks with `Bridge/Cir/PtrArgs`; `using I`, `cir_hrun`, `cir_loop_pair`),
`equiv_aeneas` / `equiv_aeneas_straight` / `equiv_aeneas_pure`, `equiv_ts` / `equiv_ts_auto` /
`ts_lockstep`, `cobol_wp`; see each `Bridge/<E>/STATUS.md`.
