## CBACT04C → Rust on every input (2026-10-24, helper; `Demo/Cobol/Cbact04cRust/`)
- Target: `examples/rust/cbact04c/src/lib.rs`, the business logic of CardDemo's CBACT04C as in the Java
  port (`examples/java/cbact04c`): slices of `Cat`/`Account`/`Disc`, `i64` cents and rates, account ids
  `i64`, type codes `u16` and group ids `u128` (big-endian EBCDIC bytes, so `DEFAULT` is
  `0xC4C5C6C1E4D3E3404040`), the transaction count `u32`; explicit truncations; the current account held
  as a copy (`Option<Account>`, like `READ … INTO`); the last account not posted. Charon + Aeneas
  (`Demo/Gen/Aeneas/Cbact04c/`).
- Files: `Model` (`rStep`/`rRun` on integers), `Lookup` (specs of `read_account`, `find_rate`,
  `read_rate`, `post`), `RunDefs` (`RunPre`, callee equations), `RunLoop` (`run_eq`: under `RunPre`,
  `run cats accounts discs = ok (rw, n)`, no panic, `rw`/`n` = `rRun`), `Arith`/`Pure`
  (`rRun_cbact04c`: `rRun` on the input = coblean's spec; on integers no bounds are needed), `Sim`
  (`cbact04c_rust_post`, `cbact04c_rust_sim`, **`cbact04c_rust_equiv`**: `Equiv CbRelR (Rust) (COBOL)`;
  Aeneas computations are total and deterministic), `Exists` (`rust_inputs_exist`: slices and record
  functions with the hypotheses of `cbact04c_rust_equiv` exist for every input of `cbact04c_all`;
  **`cbact04c_rust_equiv_exists`**).
- COBOL side: coblean's `cbact04c_all`, the same copy as the Java migration (`Demo/Cobol/Cbact04c/`).
- Scope: as for Java (account id, balance, cycle credit and debit, group compared; transactions by
  count); the `DEFAULT` fallback branch is outside the hypotheses (the primary key is found).
- Axioms: `[propext, Classical.choice, Quot.sound]`.
