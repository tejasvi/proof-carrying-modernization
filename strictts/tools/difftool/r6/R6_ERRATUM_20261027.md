# R6 erratum (2026-10-27): counterexamples checked against the public TypeScript signatures

R6 (R6_RESULTS.md, sha256 214521cb...) fuzzes each function through its implementation signature. For
an overloaded function the implementation signature is wider than the public overloads, so a
counterexample can be a call that TypeScript code using the library could not write. Found while
checking the R6 findings against es-toolkit HEAD: `zipWith([], 8, undefined)` passes a number where every
public overload wants an array.

Check (`tscheck_cex.js`, output `tscheck.tsv`, sha256 1dbd9852f2f141f2974cd4fe15a6bf73d1bf7328198c76613d855525d62ae09c):
every one of the 86 refutations was type-checked as the call `f(<counterexample>)` against the function's
public signatures in the old and in the new version (TypeScript strict, the pair's own slice). A call
either checks in both versions or in neither:

| refutations | valid call in both versions | not a valid call (both versions) |
|---|---:|---:|
| confirmed by Lean | 9 | 0 |
| Node only | 67 | 10 |
| all | 76 | 10 |

The 10 calls outside the public signatures, all Node-only: `zip()` (0f26a676, perf; b51351f2),
`zipWith([], 8, undefined)` (e37b2957, perf), `zipWith` with one argument (a46806bb), `delay(0,
{ signal: {} })` ({} is not an AbortSignal), `repeat` with a boolean, `random` (2: no overload matches),
`template` with 3 arguments, and `orderBy` (no overload matches).

Corrections to R6_RESULTS.md:
- "86 counterexamples": 76 are calls that the public types admit (9 also confirmed by Lean). The other
  10 are differences of the implementation outside the public API, and count as such.
- "Six commits typed perf, refactor or style changed observable behaviour": four have counterexamples
  that the public types admit. Those are `uniq([-0])` (d7c37c9f, Lean + Node), `toPath("..")`
  (0edff252), `toPath("]")` (c739a739) and `areObjectsEqual(...)` (5cb0b788, an internal function,
  checked against its own declaration). `zip()` (0f26a676) and `zipWith([], 8, undefined)` (e37b2957) are
  calls outside the public overloads.
- PROVED pairs are unaffected: their statement quantifies over the implementation signature's inputs,
  a superset of the public ones.

Status on es-toolkit HEAD (9c0cac2e) and against lodash 4.17.21, from the external-report check
(`~/fv_disclosure/es_toolkit_20261027/`):
- `uniq([-0])` gives `[0]`, as lodash does.
- `toPath("..")` matches lodash.
- `zip()` returns `[]` again.
- `toPath("]")` still differs from lodash. It belongs to a wider class of compat path-parsing divergences
  introduced in v1.27.0 (#799), drafted as an issue for the user's review.
